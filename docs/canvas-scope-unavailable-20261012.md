# 清空画布后的任务接纳失败

## 已确认现象

用户确认删除或清空了画布数据后，数据库中的画布记录已不存在，而旧页面仍保留节点和引用。生成任务因所属画布或项目不可用被本机接纳校验拒绝，返回 HTTP 400，尚未提交生成。

旧错误投影将通用 400 归为 `invalid_params`，显示“模型不接受当前参数”，导致用户误以为需要修改分辨率、比例或时长。

## 修复

- 任务领域为缺失或不可用的归属返回 `task_scope_unavailable`，为归档项目返回 `task_scope_archived`，保留原有 HTTP 状态和接纳校验，不暴露内部仓库错误。
- 前端在 HTTP 参数错误的默认分类前识别这些原因，显示 `workspace_unavailable` 和打开有效画布、先新建或导入的指引。
- 旧节点的明确本地失败摘要也会得到正确展示。排查信息标明“本机画布或项目校验”，没有请求 ID 时说明“未发起模型请求”。普通上游 400 仍保留参数错误分类。
- 未为已删除画布绕过校验，也不自动恢复或覆盖用户删除的内容。

## 数据保护与用户选择

排查开始时已先保全 IndexedDB 的 322 个文件和一致的 SQLite 备份，并仅在复制出的独立浏览器 profile 读取缓存。关闭前的草稿保留在证据备份中。用户随后明确选择“保留清空结果，从新画布开始”，因此没有恢复旧画布，改为通过正常受保护 API 创建空的“换脸（新建）／画布 1”，读回确认初始版本为 1、节点和连线均为 0。

## 验证

任务领域专项通过；前端生成错误专项 71 项和 TypeScript 检查通过。检查涵盖本机归属失败不冒充模型参数错误、旧摘要展示、归档指引、内部原因不泄漏、真实模型 400 维持原分类。未提交付费生成，也未使用用户数据库作为自动测试 fixture。

完整桌面前端及 Windows 原生编译通过，已安装并重新打开。安装前逐文件备份 622 个数据文件，安装后数据库完整性正常，38 条任务、29 条 Agent 记录及唯一的新画布保留；新画布读回仍为初始版本 1，零节点、零连线，未恢复已删除画布。素材、插件和设置密钥共 500 个仍保留文件哈希一致；启动时既有清理删除 6 个无当前业务引用的资源，其文件已备份。MCP 11 工具只读冒烟通过。
