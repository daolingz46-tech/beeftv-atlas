# 画布文本阅读与放大编辑

## 改动

提示词面板的原放大入口位于被紧凑界面隐藏的标题栏中，并且只支持图片与视频。现在将入口移到输入框右上角独立展示，文本、图片、视频和音频都可打开现有的大弹窗，默认尺寸为 1200 × 640，并按视窗大小收敛。弹窗和原输入框使用同一份草稿、素材引用与生成配置，关闭或 Escape 不会丢失已输入内容。弹窗采用现有 `AppModal flush` 外壳，继续支持手动调整大小。

画布在捕获阶段接管滚轮，原文本组件在冒泡阶段阻止事件已经太晚。现在选中文本节点或进入文本编辑时，内容区域声明现有的滚轮边界，让普通纵向滚轮优先滚动文本；未选中区域沿用画布导航，Ctrl／Command 加滚轮继续缩放。普通文本、结构化富文本和内联编辑共用这项边界，滚到上下边界时不带动画布。

验证编辑同步时发现 Chromium 在富文本编辑器末尾的换行后无法稳定放置光标。渲染末尾增加仅用于定位光标的终止换行元素；序列化和光标字符计数均忽略该元素，避免多存一个换行。修改后在末尾按 Enter 并继续输入可保留真实换行和素材引用。

## 验证范围

- Chrome 加载真实组件与桌面构建的样式，7 项浏览器检查通过：浅色/深色弹窗、完整长文本、素材引用、滚动、粘贴、末尾换行、关闭和重新打开后草稿同步、普通/富文本节点选择后的双向滚动及边界、内联编辑、Ctrl 缩放，以及图片/视频/音频入口。
- 提示词窗口尺寸、引用编辑、引用规范化、文本引用、滚轮和节点内容的相邻专项共 22 项通过；TypeScript 检查与完整媒体资源的桌面前端构建通过。
- 所有自动检查使用合成内容和本地接口，不读取用户画布作为测试数据，不提交生成。

原生安装及数据备份的回执留在本地维护目录。此改动不调整模型、报价、任务协议、Agent 宿主或工作区保存机制。

Windows 原生编译通过，安装前正常关闭应用并逐文件验证 571 个数据文件的完整备份。已替换桌面程序并重新打开；安装后数据库完整性正常，原有 37 条任务、8 个画布、205 条资源和 27 条 Agent 业务记录保留，素材、插件及设置密钥共 471 个文件哈希一致，未触发资源清理。MCP 11 工具的只读连接、模型与任务列表冒烟通过。
