# Agent 渠道失败的原因投影

## 已确认原因

原生助手在 Ling-3.1-Flash 渠道中收到 HTTP 402，上游代码为 `insufficient_balance`，信息为 API Key 已欠费。官方 Durable 提交为 `unanswered / model_error`。再次发送继续要求仍得到同样的 402；宿主没有发生工具写入。

旧界面只根据 `model_error` 展示“模型没有完成回复”，并提供“继续处理”。这隐藏了可处理的原因，导致在渠道状态未改变时继续发送相同请求。

## 修复边界

- 宿主将官方 SDK 的 HTTP 状态及明确额度错误代码投影成稳定原因：余额、认证、权限、参数、模型或接口不存在、限流、服务不可用。识别后的输出使用固定文案，不将上游请求或凭据细节外发。
- 新 Durable 结算、旧 JSONL 结算及两种历史读取采用同一投影。读取旧记录时不改写官方 journal、不创建回合或重新提交工具。
- 余额、密钥、权限及配置问题不展示原地继续按钮，提示修正渠道或更换模型后发送。临时限流、服务故障仍支持手动继续。
- 保留原有超时、预算、授权和取消语义，以及已有节点、生成提议和撤销记录。不更改默认模型、密钥、付费生成或模型调度循环。

此补丁不能给渠道充值或恢复过期试用额度。渠道恢复或用户手动更换可用模型后，新的业务轮次通过原有官方 SDK 在同一对话继续；运行中的冻结轮次不切换模型。

## 验证

本地合成接口实际返回与故障一致的 402，通过钉选的官方 pi SDK 1.0.4、Node SQLite 和完整 Durable 会话执行，验证明确失败、持久历史读取零请求，以及手动切换模型后同一会话返回成功。合成测试不使用用户画布或密钥，不提交付费任务。

相邻回归覆盖旧 JSONL 历史投影、不变更操作记录、取消与预算优先级，以及助手卡片的文案和按钮。具体运行回执与安装备份保存在本地缓存和维护记录中。

本次通过宿主纯函数专项 29 例、前端展示/历史/预算专项 20 例、隔离进程运行的流协议专项 28 例、官方 Node SQLite 模型切换与失败专项 4 例，以及现有 Durable 崩溃、恢复、停止和历史专项。TypeScript 检查、完整媒体资源的桌面前端构建和 Windows 原生编译通过。

初次组合运行时，已有测试的全局 mock 相互影响；流协议专项单独运行后 28 例通过。已有旧 JSONL 用例依赖 POSIX `chmod` 限制目录写入，该条件在 Windows 不成立，未将它计入通过数。相邻 Durable 模型切换测试的子进程路径改为 `fileURLToPath` 后，在 Windows 通过真实进程恢复验证。

安装替换原生程序与两个原有宿主模块，并增加错误投影模块；官方 SDK 依赖和模型配置不变。正常关闭后备份全部 510 个数据文件及旧程序和被替换模块，重启读取两个实际会话，原有 11 条余额失败全部投影为明确原因；读取历史零模型请求。32 条任务、6 个画布及安装前 14 条 Agent 业务记录保留，原有仍使用的素材、插件和设置密钥共 440 个文件哈希一致。启动时既有自动清理移除 8 个资源，备份数据库中它们仅出现在历史操作回执、没有当前业务引用；对应文件已在安装前备份。MCP 的 11 工具只读冒烟通过，不提交付费生成。
