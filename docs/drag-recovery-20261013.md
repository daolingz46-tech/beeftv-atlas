# 系统拖拽回退记录

## 故障与确认

用户反馈打开新增拖出功能的客户端后，画布节点、资源管理器以及微信的拖拽都失效；关闭 BeefTV 后其他软件恢复正常。现场检查时客户端已关闭，未发现遗留的拖拽测试进程、鼠标捕获或按住的鼠标／修饰键。

这一开关对照将故障范围指向客户端新增的系统拖拽功能。故障期间没有保留下原生线程堆栈，不能将具体阻塞点报告为已确认。

## 实现与验收缺陷

- 媒体区域的普通拖动直接进入原生文件拖拽，并跳过节点位置更新，改变了原有画布拖动语义。
- Windows OLE 拖拽是阻塞式系统交互。进入原生阶段后，`CancelNodeFileDrag` 不接受前端取消；客户端退出路径也没有明确取消这一会话。上下文超时依赖 OLE 回调执行，不能保证在系统调用阻塞时及时退出。
- 独立浏览器和原生文件接收测试只能证明各自的局部合同。此前未完成实际 Wails 客户端中进入／退出拖拽、切换软件及重复拖动的联合验收，却按已完成交付，这是验收缺陷。

## 本次处理

撤回 `9394332` 和 `aa58568` 两次拖出功能提交，运行源码恢复到 `8335015`。正式程序恢复为添加该功能之前已备份、已校验哈希的可执行文件。只替换程序，不恢复旧数据库或旧素材；最新项目数据先单独备份，再与重新打开的客户端校验。

这次回退删除原生拖出入口及其前端接管逻辑。此前的下载、右键复制、普通节点拖动和 Alt 复制保持基线实现。未修改 Windows 注册表、其他软件或系统设置。
